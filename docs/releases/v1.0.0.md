# DaamRadar v1.0.0 release guide

Prepared **30 October 2026**. Application verification is complete for the revision below. **The release files are not committed and the `v1.0.0` tag has not been created by this preparation.** Commit these files, validate that final revision, then tag it using the commands below.

## Included in v1

A locally runnable grocery comparison and planning application: search and offer filters, dated observations and history, standard-unit prices, compatible pack-size comparisons, saved shopping lists and budgets, print/PDF checklists, target-price watchlists, portable planning backups, source freshness, catalog-quality review and explicit bounded collection controls. See the [README](../../README.md), [changelog](../../CHANGELOG.md) and [Demo screenshots](../screenshots/README.md).

Source code is distributed under the [MIT license](../../LICENSE). Bundled third-party notices remain applicable, including [Bootstrap's notice](../../static/vendor/BOOTSTRAP-LICENSE.txt). Retailer content remains subject to its own rights and access conditions.

A Git clone or source ZIP contains no development database, `.env`, accounts, collected catalog, logs or browser-saved plans. The README quick start creates a local database with twelve fictional Demo products and thirty-six listings. No retailer request is needed to explore it. Local admin access requires creating your own account. Browser plans belong to the current origin/browser; use the JSON backup controls to move them.

## Reproduce a fresh installation check

From an installed Git checkout, with Python 3.12/3.13 and internet access for dependencies:

```powershell
.\.venv\Scripts\python.exe scripts/verify_install.py --ref HEAD
```

On macOS/Linux use `.venv/bin/python` instead. The verifier exports the selected **committed** revision into a new directory under ignored `reports/`, creates a new venv, installs the lock file from public PyPI without pip's download cache, then initializes and checks disposable databases. It neither runs manual collectors nor modifies your local database/configuration. It removes its temporary export and writes local phase logs plus `reports/fresh-install-validation.json`. Git is required for this developer verification tool; users can still run the application from a ZIP without Git. Uncommitted changes are excluded from the selected revision.

## Commit, verify and tag

Run from the repository root. Review the staged files before committing:

```powershell
git status --short
git add LICENSE CHANGELOG.md README.md docs/roadmap.md docs/continuous-integration.md docs/data-science-case-study.md docs/releases/v1.0.0.md docs/screenshots scripts/verify_install.py
git diff --cached --stat
git diff --cached --check
git commit -m "Prepare v1.0.0 local release"
git push
```

Run the fresh-install verifier again for this new `HEAD`. Open **GitHub → Actions → CI**, select the run for the pushed commit, and confirm all four matrix jobs passed. Confirm `git status --short` is empty and `git rev-parse HEAD` matches that CI run. Then create the annotated tag on that reviewed commit:

```powershell
git tag -a v1.0.0 -m "DaamRadar v1.0.0"
git show --no-patch v1.0.0
git push origin v1.0.0
```

If the tag already exists, inspect it before proceeding; do not replace it with a force push. A Git tag does not automatically create a GitHub Release page. Optionally draft a GitHub Release from the existing `v1.0.0` tag and use the notes below. Attach only intended source artifacts, excluding local databases, credentials and logs. This guide records the preparation state; the published tag and its CI run establish the final release revision.

## Suggested release notes

DaamRadar v1.0.0 is a local-first Pakistani grocery comparison and planning app. Download the source, follow the README quick start and explore fictional Demo data with no retailer credentials or hosting account. Features include dated price comparisons, pack-size and unit-rate views, shopping lists, budgets, target-price watchlists, printable checklists and portable planning backups. The project includes conservative matching, source provenance, catalog-quality review and manual bounded collection tools.

Python 3.12 or 3.13 is required. SQLite is the local default; PostgreSQL is supported. The author's collected database is not distributed. Demo prices are fictional; collected prices are dated observations and exclude delivery/checkout charges. Coverage is limited, delivery areas remain unverified and no delivered-cost savings are promised. Hosting, analysis notebooks and a measured matching benchmark are outside this release. Source code uses the MIT license.
